# KiCad MCP 与实时 PCB 编辑

本参考适用于 mixelpixx/KiCAD-MCP-Server。其他 MCP、KiCad 版本或 EDA 的行为需重新核实。调用前发现实际工具及其参数，不复制历史工具总数或过时的间接 `execute_tool` 调用方式。[上游工具发现说明](https://github.com/mixelpixx/KiCAD-MCP-Server/blob/main/docs/ROUTER_QUICK_START.md)

## 正确绑定实时板

1. 检查用户当前窗口与保存状态。KiCad PCB 编辑器需打开目标 `.kicad_pcb`，KiCad 设置中的 Plugins → Enable KiCad API 需启用。工程管理器打开不等于 PCB 编辑器已打开。[KiCad 10 官方文档](https://docs.kicad.org/10.0/en/kicad/kicad.html)
2. 确认服务依赖和后端就绪。工具列表可早于 Python 工作进程就绪，不能把“已列出工具”视为“PCB 可读写”。
3. 调用实际存在的 `open_board` 或 `open_project` 打开**与 GUI 相同的绝对路径**，再调用 `get_backend_state`。
4. 除板路径一致、`sessionBackend=ipc`、`realtime=true` 外，还要从当前文档/`get_board_info`实际读到目标板的对象和后端；状态字段不能单独证明PCB已打开。工程管理器或旧会话可以仍显示已连接。后续连接失败、窗口变化或返回文件后备时重新核实，稳定会话不必每次操作重复启动检查。
5. 检查每次写操作结果的后端和读回值。工具调用成功、`_backend=ipc`、GUI/独立 IPC 读回和磁盘已保存是不同事实，分别记录。

目前的 `KICAD_BACKEND=auto` 可以同时提供 IPC 和文件后备接口。已固定为 SWIG 的工程不会因为后来打开了 GUI 就自动升级；要在同一块板已打开时重新绑定。GUI 关闭或连接失效后不能继续声称实时编辑。[后端分派及会话绑定](https://github.com/mixelpixx/KiCAD-MCP-Server/blob/main/python/kicad_interface.py)

## 文件模式和实时模式的边界

上游仅部分工具提供 IPC 实现。准备执行不熟悉的操作时，核对当前工具输出及源码/文档的能力说明；不能把存在工具名称当作支持实时修改的证据。

- 优先通过已安装且可调用的MCP执行其真正支持的EDA操作；有可用GUI控制时用原生交互功能。MCP只是接入方式，工具名不保证调用KiCad对应的完整原生功能。不因工具名陌生就另建桥接脚本或更换服务器；重复检查与导出可使用官方CLI。
- 用户要看着绘图时，围绕当前器件或功能块展示实际变更；先核对目标路径、进程和未保存状态，复用已有编辑器窗口。原理图若只能写磁盘，则按保存/关闭、修改、校验、重新打开的单一状态流程展示阶段结果，明确它与PCB实时IPC的差别；不能用重复开窗口或空白预览冒充同步。

- 需要实时同步而工具只能修改文件时，先寻找语义等价的实际 IPC 操作。若没有，解释差别并安排单一状态来源，保存/关闭相关窗口后进行文件编辑，再重新加载。不要让磁盘文件与 GUI 各自保存不同版本。
- 保存实时板使用当前版本确认支持 IPC 的保存操作；不能假设所有 `save_*` 都走相同路径。未保存的 GUI 状态应明确保留，禁止用旧磁盘文件覆盖。
- 对暂时的启动或库加载超时，先查看后端状态和日志。读操作可在就绪后重试；写操作结果不明时先读回 UUID、位号、坐标或网络，避免重复放置。持续失败时修正明确的原因，或报告当前限制，不无限重试。
- 文件模式若报告`diskChangedExternally=true`，读取旧缓存也可能得到看似正确的单个器件，不能据此覆盖整板。确认磁盘是最新主文件、无待保留的GUI或MCP未保存修改后，用`open_board`刷新内存，再核实变化标志已清除；该操作不等于开启实时模式。未保存状态来源不明时先保留双方状态，不盲目重新加载或保存。
- 新接口验证使用副本，添加带唯一标记的对象，读回身份后只删除该对象。不能清空整板来代替测试清理。

## 2026-09-09 的已验证行为

在 KiCad 10.0.5、服务 2.7.0（提交 `b420ff7edacf64d5b1259a1acff33ead17d506c1`）上，已验证 `get_backend_state`、`open_board`、`get_board_info` 和 `add_board_text` 的实时路径。曾用独立 `kipy` 客户端读回相同文字/UUID，再事务删除该唯一测试文字，GUI 截图也确认可见。

这次验证发现两个具体边界：`delete_graphic` 不在该版本的 IPC 分派清单中；`add_board_text` 虽收到字号 2 mm，IPC 实际使用默认 1.27 mm。遇到这些操作应重新核实当前版本，不能宣称所有属性和工具都经过测试，也不要把这个历史问题扩展为所有版本的结论。

独立 IPC 操作使用官方 `kicad-python`（导入名 `kipy`）文档和已安装类型；读取 `board.document` 确认文件，按 UUID 修改明确对象；事务失败时按当前 API 撤销未提交事务。[官方 Board API](https://docs.kicad.org/kicad-python-main/board.html)

## 原生功能与接入能力（2026-09-10补充）

KiCad 10自身提供交互式推挤/绕障、差分布线、长度和偏斜调整、网络检查及从原理图更新PCB。[官方PCB手册](https://docs.kicad.org/10.0/en/pcbnew/pcbnew.html) 这些应优先于自行生成几何路径；能否由当前AI操作，仍取决于实际GUI控制或接口能力。

当前安装的服务2.7.0中，`commands/routing.py`的`route_trace`直接创建`PCB_TRACK`；`route_pad_to_pad`查找焊盘后添加线段，`route_differential_pair`按偏移生成线段。它们不能据此视为调用了KiCad原生推挤、绕障或时序调长。`autoroute`则导出DSN、运行外部Freerouting、导回SES；“已加线”或外部评分提高均不等于原板规则和时序通过。以后版本须以实际实现为准，不为确认简单操作反复读取全部源码。

本次还观察到：批量移动不支持已由IPC管理的板；一次翻到底面并旋转时，最终角度可能与预期不同。用一个真实代表器件核对层、角度、焊盘坐标后再扩大操作；不要换用磁盘批处理绕过GUI的未保存状态。

### 验证和停止条件

本节约束接入和自动算法试验，不限制正常设计中的调位、局部重布和纠错。一次试布不通是检查具体布局的线索，不能据此判定整板无法设计。

- 新接入先读目标对象，再做一个可撤销、可读回的代表操作。代表性应覆盖即将使用的层变换、BGA/密集障碍或网络特征；空板四条线成功不足以批准整板自动布线。
- 若一轮工具试验失败，只在定位原因后做针对性重试；同类故障重复且无新原因就停止该方法。外部自动布线若确有必要，先设相称的时间检查点和通过标准，不默认多轮择优；检查点用于决定是否值得继续，不是整板设计的完成时限。有代表试验和实际进展依据后才扩大运行规模。
- 通过标准同时包括真实连接改善、无新增关键违规、保留关键网络约束。报告计数可截断，局部检查也不能覆盖相邻功能块；接纳候选时按完整工程检查接触边界。
- 跨格式导出/导入先核查网络、层映射和铜区。此次DSN试验发现重叠优先级铜区与多轮廓不能假设原样保留；出现语义丢失时停止使用该交换路径，不能靠继续跑布线修复，也不默认另写几何转换器。
- 接入缺少原生布线/调长时，只继续当前能力能可靠完成的内容，并清楚标出剩余操作。不得把软件本身具有功能写成AI已能控制该功能；不得为缩短耗时关闭电气规则或遗漏关键验证。

## 可移植性与本机接入

没有 MCP 的其他 AI 可以使用其拥有的 EDA/CLI/文件编辑能力，沿用主技能的资料和验证要求。不得伪造实时 UI 观察。不得为了加载本技能就自动重新安装 KiCad、运行第三方安装脚本或改变其他工程配置。

本可移植版本不携带个人机器路径或接入配置。首次接入时检测当前解释器、库路径与客户端配置；同一稳定会话复用已核实结果，不反复安装或扫描环境。
